What a stopped run looks like

Three runs of the free lite version. First the rules are in place and the run may start. Then someone deletes the rules line from the router. Then someone switches off one check inside the gate itself, and the planted tests catch that too.

Real output of the lite version, captured Oct 26, 2026. A stopped run exits with code 1, so a scheduler or a CI job sees the failure too. A text check cannot judge what a sentence means, so the router carries two required lines word for word: change, delete, comment out or fence either one and the run stops. Every size limit is tested at the limit and one byte under it.

The four things people fear from an unattended agent, and what the full kit is planned to do about each

  • It spends money

    Spend and account rules it reads before every run: nothing bought, no card or password typed, no account created or terms accepted without your word in a live chat.

  • It deletes things

    No delete without your word naming the thing, a _to_delete folder instead, and a hook that blocks the commands you list before they run.

  • It sends something wrong

    A send gate: an email, post or deploy goes out only on a template you approved and nobody has changed since, under a daily cap, with a stop word.

  • It drifts from your rules

    The rules load first on every run and stay small enough to load in full. A failed check stops the run instead of passing quietly.

How it works

  1. The router loads first

    CLAUDE.md names the rulebook, the live state and the one job this run does. Each layer has a size cap, so the rules stay small enough to load in full on every run.

  2. One job per skill

    Each SKILL.md says what the job reads, what it does and what it writes. A job that only writes a report has no step that sends anything.

  3. A preflight on every run

    The gates run before any work. One ERROR line stops the run and says why. Planted tests check that each gate still catches its case.

Who it is not for

  • You want a hard sandbox. Rules in a file guide the model; real limits come from permission settings, containers, separate accounts, spending caps and backups. The full kit is planned to set up the first and tell you where the rest go.
  • You watch every step of every run. You do not need gates.
  • You want an agent that spends or sends without review. The full kit is planned to require your word first.
  • You need a compliance or security certification.
  • You will not edit a rules file. The kit only works once the rules are yours.

Questions

Does a rules file really stop an agent?

Not on its own. A model can misread a rule. The full kit is planned to pair the rules with checks in code that run before the work, permission settings that block commands outright, and a stop when any check fails. The lite version has the checks and the stop.

Does it work with agents other than Claude Code?

The layout and templates are written for Claude Code. The gates and tests are plain Python, so another agent that reads a project file and runs shell commands can use them with small edits.

What do I need?

Python 3.8 or later. No packages, no service to sign up for, no account with us.

Is this a security product?

No. It is a way to write down your rules and check them on every run. It is not a sandbox, an audit or security advice.
