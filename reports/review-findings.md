# Reviewer findings that needed a round 2

Each builder or promote run that passes only on round 2 adds its findings here; the COO folds repeats into the defaults.

- Oct 5, 10:50 pm, cloud builder, Fair Share Chore Chart: (1) a preview image showed a truncated list with the full-list total, so visible rows did not add up; show "+N more" and label the total. (2) a fixed print area with empty person columns shrank the printable chart to 5.5 pt; design printables as one list that fits any count. (3) a user-added row with a blank Include flag was silently ignored; every input row needs a Check message. (4) to (6) clipped labels and a header that misdescribed the sort order.
- Oct 6, 7:05 am, morning promote, pin #18 expense tracker: a pin card listed Sales, two highlighted costs and the month's net as consecutive rows, so the visible rows read as a subtotal that did not add up ($858 - $413 - $350 is not -$165). When a pin shows only some of the costs, put them under a sub-header like "Two of January's costs" and put the net under "after all costs". Round-1 notes for future renders: label a rounded discount price "rounded up", and give the floor its own caption in demo Shorts.
- Oct 6, 4:00 pm, cloud builder, Freelance Income Tracker: (1) a per-client summary keyed on names typed on another tab silently drops log rows when a client is renamed, while the status line still says everything is counted; any lookup-keyed total needs a "rows not matched" check folded into the sheet's own error count. (2) Help text promised dates "stay as you typed them" and that a typo can't become another day; claim only what validation does (real dates only, shown with the month name) and use locale-neutral examples (Oct 1, 2026, not 10/1/2026). (3) Never name an app (Numbers) or an Excel test in copy unless that test ran; say "Made for" otherwise.
