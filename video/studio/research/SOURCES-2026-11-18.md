# Which record sources our runs can open (BUILD-2026-11-18.md Part A step 7; tested Nov 18, 2026)

Three readers, tested the same morning. Shell = curl from the cloud session (what scripts and tools/ use). Box = the GEEKOM page reader (pnf-local-jobs scripts/fetcher.py, job hosts-reach-2026-11-18-r1 to r6). WebFetch = the chat tool.

## The finding
- Shell: FAIL on every host below (the cloud environment's network allowlist refuses the tunnel: HTTP 403).
- Box: FAIL on every host but ftc.gov (the reader's own ALLOWED list, set on the box: status not_allowed).
- WebFetch: works on any page whose address came from a WebSearch result in the same session (KRDO, WRTV, JLC, WPXI, WAFB, CBS all read today). An address typed from a file asks a person for approval; with nobody there (a scheduled run) it fails. That is the likely reason 5 make runs since Nov 12 read no source: they opened the bank's addresses directly. Fix in the SKILL and the schedule: search first, then fetch the result's own address.
- So no host setting is needed for story reading. Opening hosts in the cloud environment would only let scripts (shell) read them; that is Todd's call, with the list below ready.
